# Velomux release policy — Windows test builds and reviewed draft releases

The source is currently `0.3.1-preview` and not publicly release-cleared. There is no approved application `LICENSE`, registered official GitHub repository, or reviewed FFmpeg redistributable bundle in this source package.

1. **Development runs:** Trigger **Build Windows test installer** in GitHub Actions. This read-only workflow builds, tests the actual Qt window, freezes the Windows app, tests the frozen app, creates the Inno installer, silently installs/tests/uninstalls it, and uploads a temporary Actions artifact with checksums and build provenance. It must not publish a Release.
2. **Independent Windows test:** Test the installer on a Windows 10/11 x64 machine without a system Python/FFmpeg installation. Check core audio/video/image conversions, metadata, cancellation, repaired incomplete outputs, source preservation, settings, install/upgrade, and uninstall. This is independent of CI because GitHub Windows runners already contain other development software.
3. **License + binary source approval:** Choose/approve the application's open-source license; complete `THIRD_PARTY_NOTICES.md` and required third-party texts. Select and review a specific FFmpeg ZIP, record the exact archive and executable SHA-256 hashes, source revision, codecs/configuration and license variant in `vendor/ffmpeg/BINARY_MANIFEST.json`. Provide accurate `PROVENANCE.md` and `SOURCE_OFFER.md`. Assess Qt/PySide6 and Python/Pillow redistribution requirements. No blank or invented hashes or obligations.
4. **Official repository and version:** Set `version.py` `GITHUB_REPOSITORY` to the approved `owner/Velomux`, reconcile app version, installer version, release notes and the existing `v<APP_VERSION>` tag. Confirm branch/tag protection and maintainer review.
5. **Reviewed draft:** With preconditions met, manually run **Stage reviewed Windows GitHub release (DRAFT only)** with the existing tag and the manual review acknowledgment. Its build obtains the exact manifest-pinned FFmpeg ZIP, validates hashes, runs Windows tests, and creates a draft prerelease with setup, portable, checksums and GitHub's source archives. A failure blocks the draft.
6. **Publication:** A maintainer separately checks release artifacts, archive structure, installed GUI, FFmpeg origin, notices, source/binary hashes, signatures if available, and release notes before publishing. A successful CI run alone does not constitute legal or release approval.
7. **Subsequent updates:** Repeat source/codec checks and the install/upgrade regression checks; ship application/FFmpeg updates through reviewed versioned installer releases. The current Update Center offers only a manual release check, not unattended binary updates.

Full details: [GITHUB_BUILDS_AND_UPDATES.md](GITHUB_BUILDS_AND_UPDATES.md).
